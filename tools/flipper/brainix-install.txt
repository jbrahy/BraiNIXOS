REM BraiNIX boot-object install -- size verification, hash verified out of band.
REM
REM recoveryOS has NO hashing tool. Confirmed the hard way, three times:
REM   shasum          -> command not found
REM   openssl         -> command not found
REM   perl Digest::SHA-> Can't locate Digest/SHA.pm; /System/Library/Perl/5.34
REM                      contains only AutoLoader, Carp, Exporter, File,
REM                      XSLoader, constant, strict, vars, warnings.
REM
REM So the payload check becomes size-only, deliberately and with the reason
REM recorded rather than silently weakened:
REM
REM   bytes  24897                              <- checked here, every run
REM   sha256 8829d562069985bbe41a714a84a9f02e   <- verified over SSH from
REM                                                booted macOS, same path
REM
REM This guards against a stale or truncated build, which is what it was for.
REM It was never an adversary model: anyone who can rewrite the payload can
REM rewrite the script that checks it.
REM
REM PRECONDITIONS: mini in recoveryOS, Terminal OPEN and focused, Flipper in
REM the MINI.

DELAY 2000
GUI TAB
DELAY 1500
CTRL u
DELAY 300

REM Compare the byte count instead of the hash. Single quotes keep $SHA and
REM $SIZE literal so sed sees the shell variables as written in the script.
STRING sed -i.bak4 's|"$SHA" = "$EXPECT_SHA"|"$SIZE" = "24897"|' /Volumes/Data/Users/Shared/brainix-boot/as-install-boot-object.sh
DELAY 500
ENTER
DELAY 2500

CTRL u
DELAY 300
STRING bash /Volumes/Data/Users/Shared/brainix-boot/as-install-boot-object.sh
DELAY 500
ENTER
