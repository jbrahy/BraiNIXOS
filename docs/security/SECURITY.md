## Phase 08 Security Notes

### T-DEV-020 Severity Assessment

T-DEV-020 is rated MEDIUM in the threat register. Under `block_on: CRITICAL,HIGH` this is not a hard blocker. However, the grub.cfg discrepancy between SUMMARY.md documentation and the on-disk file should be investigated:

- Git status shows `M iso/boot/grub/grub.cfg` (modified but uncommitted or modified after commit `caf741d`)
- The current file content has no `module` or `module2` lines whatsoever — it cannot load any server binary
- This means devd-nic.elf and devd-disk.elf would not be loaded by the bootloader at runtime
- Recommended action: verify the grub.cfg change was committed and the working tree reflects the committed content

### T-DEV-011 / T-DEV-012 Fail-Closed Disposition

The plan specified these handlers would return `0` (success stubs). The last commit message (`fix(08): close T-DEV-011/012/018`) changed both handlers to return `-1`. This is a security improvement: callers observe failure rather than false success before full validation is wired. The fail-closed behavior is verified by reading both handler files.

### Structural Approximations (T-DEV-014, T-DEV-015, T-DEV-016)

Three process teardown functions (`deallocate_process_pages`, `deallocate_process_thread`, `remove_process_from_scheduler`) use documented structural approximations because the process table is not wired in Phase 8. Each function documents its gap inline and references the subsystem that will provide full wiring in Phase 9. The `ProcessExitRecord` test verifies all four steps report completion, confirming the scaffolding is correct. These are accepted Phase 8 scope limitations, not security gaps.
